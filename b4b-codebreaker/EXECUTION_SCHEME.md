# B4B CodeBreaker Tutor Execution Scheme

## Purpose

This document defines the autonomous execution scheme for completing the B4B CodeBreaker Tutor system without needing repeated user approval for every next step.

The goal is to finish the whole product layer in a structured, repeatable, premium way.

## Core Direction

AI Engineering from Scratch is the source curriculum.

B4B CodeBreaker Tutor is the learner transformation layer.

The system must translate the curriculum into:

- Beginner-safe starter paths
- Lesson-by-lesson CodeBreaker locks
- B4B learning method documentation
- Pop-culture bridge libraries
- Learner evidence templates
- GPT upload assets
- Quality assurance files
- Product packaging files

## Operating Rule

When a phase starter path is complete, create the matching lesson-by-lesson CodeBreaker lock file.

When both files are complete for a phase, move to the next priority phase.

Do not ask for permission between these steps unless there is a repo conflict, missing source information, or a safety concern.

## Phase File Pattern

Each priority phase should receive two files:

```text
b4b-codebreaker/curriculum-adapter/phase-guides/phase-XX-[phase-name]-starter-path.md
b4b-codebreaker/curriculum-adapter/phase-guides/phase-XX-codebreaker-locks.md
```

## Starter Path Requirements

Each starter path must include:

1. Purpose
2. Phase doctrine
3. Recommended teaching order
4. Beginner-safe concept ladder
5. Smallest Useful Truths
6. Pop-culture bridges
7. Where each analogy works
8. Where each analogy stops
9. First CodeBreaker locks
10. Boss Lock
11. Tutor notes
12. Misunderstanding warnings
13. Evidence checks
14. Completion criteria
15. Next recommended file

## CodeBreaker Locks File Requirements

Each CodeBreaker locks file must map the actual lessons in that phase into challenge sequences.

Each lesson challenge should include:

1. Lesson title
2. Challenge name
3. Lock type
4. Difficulty
5. Concept
6. Smallest Useful Truth
7. Pop-culture bridge
8. Where the analogy works
9. Where the analogy stops
10. Mission
11. The Lock
12. Hint
13. Break Condition
14. After Unlock summary

Each phase must end with a Boss Lock that combines the major concepts.

## Quality Standard

Every file must support one or more of these outcomes:

- Reduce confusion
- Translate complexity
- Create evidence
- Support GPT deployment
- Support learner progress
- Support product packaging

If a file does not support one of those outcomes, it should not be created.

## Tone Standard

The system should feel:

- Clear
- Warm
- Smart
- Grounded
- Playful when useful
- Accurate before entertaining
- Beginner-safe without becoming childish

## Analogy Standard

Every pop-culture bridge must include:

- Where the analogy works
- Where the analogy stops

The metaphor opens the door.

The technical explanation walks through it.

## Evidence Standard

Every lesson path should eventually create evidence through:

- Explanation
- Prediction
- Modification
- Debugging
- Connection
- Reflection
- Boss Lock synthesis

## Completion Definition

The project is complete when a learner can use the GPT and supporting files to move from total beginner orientation through AI engineering concepts with:

- A clear path
- Beginner-safe explanations
- Proof-based challenges
- Learning evidence
- Progress tracking
- Product-ready GPT instructions
- Premium packaging structure

## Next Action Protocol

After completing any file, choose the next action using this order:

1. Finish the matching file for the current phase.
2. Move to the next priority phase starter path.
3. Create the next priority phase CodeBreaker locks file.
4. Fill missing GPT system files.
5. Fill missing B4B method files.
6. Fill missing learner system files.
7. Fill missing pop-culture bridge files.
8. Fill export and packaging files.
9. Create QA and productization files.

This scheme authorizes forward execution until the full B4B CodeBreaker Tutor product layer is complete.
