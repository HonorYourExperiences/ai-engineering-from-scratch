# Phase 0 CodeBreaker Locks: Setup & Tooling

## Purpose

This file turns the actual Phase 0 lessons from AI Engineering from Scratch into beginner-safe CodeBreaker Challenges.

Phase 0 is not just technical setup.

For a true beginner, Phase 0 is the workshop door.

The learner is not only installing tools. They are learning what the tools are, why they exist, and how to respond when the machine talks back through outputs or errors.

## Phase 0 Challenge Doctrine

Every Phase 0 lesson should produce one clear piece of evidence.

The learner should not leave a lesson saying only, “I read it.”

They should leave saying:

“I proved I understand what this tool does and what my next safe action is.”

## Difficulty Progression

- Spark Lock: recognize and explain
- Signal Lock: predict and interpret
- Circuit Lock: perform or modify one small action
- System Lock: connect multiple tools into a workflow
- Boss Lock: combine several Phase 0 concepts

# Lesson 01: Dev Environment

## CodeBreaker Challenge: Workshop Setup 001

### Lock Type

Connect

### Difficulty

Signal Lock

### Concept

Development environment

### Smallest Useful Truth

A development environment is the set of tools and settings used to build and run code.

### Pop-Culture Bridge

A development environment is like Iron Man's workshop.

The suit is not built from desire alone. Tony needs the workspace, tools, power, parts, screens, and testing area.

### Where the Analogy Works

Both a workshop and a development environment prepare someone to build and test things.

### Where the Analogy Stops

A development environment is software configuration, not a physical lab.

### Mission

Explain why a beginner needs a development environment before building AI projects.

### The Lock

Complete the sentence:

A development environment helps me ______ code.

### Hint 1

Think build, run, test, and fix.

### Break Condition

The learner explains that a development environment helps them build, run, test, and debug code.

### After Unlock

The learner proved they understand setup as workshop preparation.

# Lesson 12: Debugging & Profiling

## CodeBreaker Challenge: Signal Reader 001

### Lock Type

Explain

### Difficulty

Circuit Lock

### Concept

Debugging and profiling

### Smallest Useful Truth

Debugging finds what is wrong. Profiling finds what is slow or expensive.

### Pop-Culture Bridge

Debugging is like finding why the car will not start. Profiling is like finding why the car uses too much gas.

### Where the Analogy Works

Both involve diagnosing a problem through evidence.

### Where the Analogy Stops

Code problems are found through messages, tests, logs, timing, memory use, and system behavior.

### Mission

Separate debugging from profiling.

### The Lock

Your code crashes. Your code runs but takes too long. Which one sounds like debugging, and which one sounds like profiling?

### Hint 1

Crashing means broken. Slow means performance.

### Break Condition

The learner explains that crashing points to debugging, while slow performance points to profiling.

### After Unlock

The learner proved they understand two different kinds of technical investigation.

# Tutor Notes

## How to Use This File

Use this file after the Phase 0 Starter Path.

The Starter Path introduces beginner vocabulary.

This file maps that vocabulary to the actual Phase 0 lessons.

## Recommended Flow

1. Teach the beginner concept.
2. Present the CodeBreaker lock.
3. Offer one hint if needed.
4. Let the learner attempt.
5. Diagnose the attempt.
6. Create a Concept Receipt.
7. Move to the next lock only after evidence.

## Evidence Standard

The learner should be able to answer:

- What is this tool?
- Why does it exist?
- What problem does it prevent or solve?
- How does it connect to later AI engineering work?
